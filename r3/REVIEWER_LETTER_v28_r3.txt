二、主程序为何改动（主程序 SHA-256 由第一节基线值改为第一节本版值）
--------------------------------------------------------------------------------
在 C 版主程序上实跑（Python 3.13.14，sys.get_int_max_str_digits() = 4300）：
    parse_version_tuple("1" * 5000 + ".0")
    RAISED = ValueError: Exceeds the limit (4300 digits) for integer string
             conversion: value has 5000 digits
VERSION_RE 的 \d+ 不限制位数，fullmatch 通过后在 int(m.group("major")) 处触发
Python 3.11+ 转换上限；C 版无异常保护，函数对外抛异常而非按契约返回 None。

修改仅在 parse_version_tuple：docstring 增 1 行说明；把三处 int() 转换包进
try / except ValueError -> return None，只捕获 ValueError，不吞其他异常。
VERSION 常量仍为 "2.8"；V1–V10、check_v8、check_python_env、
_is_absolute_like、Ctx.p 等模块未改。

改动后主验证器复跑：

    PYTHON_REPRODUCIBILITY = UNVERIFIED (config 无 generation_python 记录)

4.1 统计口径的代码事实（回应您第二节关于 N 的定义）
    您提出 N = |RESULTS| + |SKIPPED|，并担心 SKIPPED 重复计入 RESULTS。
    按 r3 源码，这两个容器不是互斥集合：skip() 同时写入两处，SKIPPED 是
    RESULTS 的 cid 子集。直接贴源码（test_verify_reviewer.py）：

    100 | def check(cid, desc, cond, detail=""):
    101 |     RESULTS.append((cid, desc, bool(cond), detail))
    102 |     print("  [%s] %-4s %s" % ("PASS" if cond else "FAIL", cid, desc))
    103 |     if detail:
    104 |         for line in str(detail).splitlines():
    105 |             print("            %s" % line)
    106 |
    107 |
    108 | def skip(cid, desc, reason=""):
    109 |     """记录"环境不具备测试条件"。与 FAIL 区分：不计入 PASS，也不影响退出码。"""
    110 |     SKIPPED.append(cid)
    111 |     RESULTS.append((cid, desc, True, reason))     # <-- 同时进 RESULTS
    112 |     print("  [SKIP] %-4s %s" % (cid, desc))
    113 |     if reason:
    114 |         for line in str(reason).splitlines():
    115 |             print("            %s" % line)

    724 |     n = len(RESULTS)
    725 |     bad = [r for r in RESULTS if not r[2]]
    726 |     n_skip = len(SKIPPED)
    727 |     n_pass = n - n_skip - len(bad)
    728 |     print("\n" + "=" * 78)
    729 |     print("统计：共 %d 项，PASS=%d SKIP=%d FAIL=%d"
    730 |           % (n, n_pass, n_skip, len(bad)))
    731 |     if SKIPPED:
    732 |         print("  SKIP 明细（环境不具备条件，不代表被测代码有问题，也不计 PASS）：%s"
    733 |               % ", ".join(SKIPPED))
    734 |     if bad:
    735 |         for cid, desc, _, detail in bad:
    736 |             print("  FAIL [%s] %s" % (cid, desc))
    737 |     print("结论：%s" % ("ALL PASS（无 FAIL）" if not bad else "存在失败"))
    738 |     print("=" * 78)
    739 |     return 0 if not bad else 1

    全文件只有两处写 RESULTS（第 101、111 行）、一处写 SKIPPED（第 110 行）。
    因此 N = len(RESULTS) 已包含 PASS / FAIL / SKIP 三类记录；SKIPPED 只是
    「其中哪些是 SKIP」的索引列表，不能再与 RESULTS 相加，否则重复计数。

    受限环境本次实测（非引用报告）：
        len(RESULTS)                = 74
        len(SKIPPED)                = 5
        RESULTS 中属于 SKIP 的记录  = 5
        SKIPPED 是 RESULTS 的 cid 子集 = True
        PASS = 69   SKIP = 5   FAIL = 0
        PASS + SKIP + FAIL          = 74 = len(RESULTS)
        |RESULTS| + |SKIPPED|       = 79（与 74 不等，若作总数会重复计数）
        SKIPPED 元素无重复           = True
        SKIP 记录均以 True 登记      = True
        退出码                       = 0

    结论：74 项 / PASS=69 / SKIP=5 / FAIL=0 在当前实现下自洽。您指出的重叠
    登记确实存在，但汇总只以 len(RESULTS) 作分母，未把两个容器相加，因此
    没有重复统计。退出码由第 739 行严格只由 bad（FAIL）决定，SKIP 不参与。
