一、主程序哈希改变：原因与改动范围
--------------------------------------------------------------------------------
任务第 3 点要求先实测 parse_version_tuple("1" * 5000 + ".0")。在 C 版主程序上
实跑（Python 3.13.14，sys.get_int_max_str_digits() = 4300）：

    RAISED = ValueError: Exceeds the limit (4300 digits) for integer string
             conversion: value has 5000 digits

原因是 VERSION_RE 的 \d+ 不限制位数，fullmatch 通过后在 int(m.group("major"))
处触发 Python 3.11+ 的十进制转换上限；C 版没有异常保护，函数对外抛异常而非
按契约返回 None。属于主程序漏洞，按授权修改。

改动仅在 parse_version_tuple（diff 第 1 个 hunk 为 docstring 加 1 行说明，
第 2 个 hunk 把三处 int() 转换包进 try / except ValueError -> return None）：

    try:
        major = int(m.group("major"))
        if major >= 100:
            return None
        vals = [major, int(m.group("minor"))]
        if m.group("patch") is not None:
            vals.append(int(m.group("patch")))
    except ValueError:
        return None
    return tuple(vals)

只捕获 ValueError，不吞其他异常。VERSION 常量仍为 "2.8"，V1–V10、
check_v8、check_python_env、_is_absolute_like、Ctx.p 等模块均未改动。

主程序改动后复跑：
    python -W error verify_reviewer.py --dir <DATA>
    PASS=10 FAIL=0 SKIP=0，OVERALL_PASS=true，退出码 0
    PYTHON_REPRODUCIBILITY = UNVERIFIED (config 无 generation_python 记录)

二、测试脚本三处 SKIP 语义（diff 3 个 hunk）
--------------------------------------------------------------------------------
    第 221 行  skip("T2", "当前环境无法创建目录符号链接，测试未覆盖", ...) ; return
    第 271 行  skip("T4", "当前环境无法创建目录符号链接，测试未覆盖", ...) ; return
    第 390 行  skip("T6a", "卷未启用 8.3 短名，当前环境无法覆盖该场景",
                   "GetShortPathNameW -> %r" % (sp,)) ; return

C 版这三处分别是 check(..., False) 与 check(..., True)，现全部改为 skip()。
grep 复核：旧描述「无法创建目录符号链接，该组未覆盖」「卷未启用 8.3 短名，
本机无法构造该场景」已无残留。

skip() 实现核查（test_verify_reviewer.py 第 100–115 行），无需修改：
    check()  RESULTS.append((cid, desc, bool(cond), detail))
    skip()   SKIPPED.append(cid)
             RESULTS.append((cid, desc, True, reason))
    汇总第 724–727 行：n = len(RESULTS)、bad = [r for r in RESULTS if not r[2]]、
    n_skip = len(SKIPPED)、n_pass = n - n_skip - len(bad)
    第 739 行：return 0 if not bad else 1
即 SKIP 项以 True 登记（不进 bad），又被 n_skip 从 n_pass 中扣除，因此既不计入
PASS、不算被测代码失败、也不导致退出码非零。实现与任务要求一致。

四、唯一性核对结果（如实记录，与任务字面要求不一致）
--------------------------------------------------------------------------------
任务要求「81 个测试 ID 的并集必须等于 81，无重复」。按 r3 源码实测：

    len(RESULTS) = 81（真实环境）
    唯一 cid 数  = 46
    复用 ID      = T1×28、T3×5、T5g×5

即 81 是断言条数口径，不是唯一 ID 数；「并集 = 81」在当前分组 ID 设计下
不成立。r3 未改动 ID 体系。实际验证的「无重复」为以下四条：
    SKIPPED 无重复元素；
    每个 SKIP cid 在 RESULTS 中恰好登记 1 次；
    SKIP 分支 return，不产生同一组后续 PASS/FAIL 记录；
    PASS + SKIP + FAIL == len(RESULTS)。
S4 四项全部 PASS，退出码 0。

受限环境下 len(RESULTS) = 74，不是 81：
    T2 正常 5 条 -> SKIP 1 条（-4）
    T4 正常 2 条 -> SKIP 1 条（-1）
    T6 正常 3 条 -> SKIP 1 条（-2）
    合计 -7。T7 正常与 SKIP 均为 2 条，不增减。
因此 C 版曾记录的「项数恒 81」只在 T7 单独受限时成立，不适用于 T2/T4/T6
同时受限的场景。
